6.  Projects / Case Studies
7.  Insights / Blog

of this work.

2.  What We Do

4.  Solutions
5.  Industries
6.  Projects / Case Studies

-   Minimal
-   Clean
-   Premium

-   No exaggerated marketing claims

# PROJECTS --- VISUAL STYLE

Project imagery should be the visual focus.

Preferred:

-   Real screenshots
-   Real website/product imagery
-   Real UI
-   Carefully cropped project photography where appropriate
-   Device/browser mockups only when they genuinely improve presentation

Avoid:

-   Stock images
-   Generic 3D renders
-   Fake dashboards
-   Invented statistics
-   Excessive device mockups
-   Huge rounded cards
-   Heavy shadows

Images should feel editorial and high quality.

------------------------------------------------------------------------

# PROJECTS --- HOVER INTERACTION

Desktop hover can be subtle.

When hovering a project:

-   image moves very slightly
-   project title brightens
-   arrow shifts a few pixels
-   metadata becomes slightly more prominent

Optional:

A very subtle image scale of approximately 1.02--1.04.

Do not use dramatic zooming.

Do not create cursor-following previews unless there is a strong design
reason.

------------------------------------------------------------------------

# PROJECTS --- SCROLL EFFECT

Use a restrained reveal.

As each project enters the viewport:

1.  Image reveals with a small upward movement.
2.  Metadata fades in.
3.  Title settles into place.
4.  Separator/line extends subtly.

Do not animate every word independently.

Do not make the projects fly around the screen.

The project itself should remain the focus.

# SECTION TRANSITION

Projects should transition into Insights naturally.

The story becomes:

``` text
INDUSTRIES
    ↓
Who we work with
    ↓
PROJECTS
    ↓
What we've built
    ↓
INSIGHTS
    ↓
What we've learned / what we know
```

This gives the homepage a logical progression from capability to
credibility.

------------------------------------------------------------------------

# MOTION SYSTEM

The entire Projects + Insights area should use a consistent motion
language:

-   short fade
-   subtle upward reveal
-   slight image movement
-   line expansion
-   restrained hover transitions

Avoid introducing a completely new animation style.

The 3D universe remains the major cinematic moment.

These sections should feel more editorial and calm.

------------------------------------------------------------------------

# RESPONSIVE PRINCIPLES

## Desktop

Use large visual project presentation and refined article layouts.

## Tablet

Reduce image size and spacing while preserving hierarchy.

## Mobile

Use one-column layouts.

Do not force desktop split compositions.

All interactions must work without hover.

------------------------------------------------------------------------

# TECHNICAL RULES

-   JavaScript / JSX only.
-   No TypeScript.
-   No new packages unless explicitly approved.
-   Keep project data separate from presentation components.
-   Keep article data separate from presentation components.
-   Use semantic HTML.
-   Use existing GSAP/ScrollTrigger.
-   Preserve Lenis.
-   Do not modify the completed Hero.
-   Avoid React state on every frame.
-   Respect prefers-reduced-motion.
-   Do not invent project clients, statistics or results.
-   Do not publish placeholder article titles as real content.
-   Use real portfolio/blog data when available.
