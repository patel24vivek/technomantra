# TechnoMantra --- Homepage Section 08

# FINAL CTA / REQUEST A PROPOSAL

## Scope

This is the final major homepage section before the footer.

Homepage story:

1.  Hero
2.  What We Do
3.  Services
4.  Solutions
5.  Industries
6.  Projects / Case Studies
7.  Insights / Blog
8.  Final CTA / Request a Proposal

The Hero and previous sections are complete or separately defined.

This section should **close the story and convert interest into
action**.

The visual direction remains:

-   Minimal
-   Clean
-   Premium
-   Professional
-   Confident
-   Spacious
-   Editorial
-   No excessive decoration
-   No generic SaaS CTA design
-   No huge collection of buttons
-   No aggressive sales language

------------------------------------------------------------------------

# PURPOSE

The visitor has now seen:

-   what TechnoMantra does
-   services
-   solutions
-   industries
-   selected work
-   insights

The final question is:

> **What should the visitor do next?**

The answer should be simple:

**Start a conversation / Request a Proposal.**

This should feel like a natural conclusion rather than a sudden sales
pitch.

------------------------------------------------------------------------

# SECTION INTRODUCTION

## Eyebrow

`START SOMETHING`

Keep it small and understated.

------------------------------------------------------------------------

# MAIN HEADING

Use:

> **Have something worth building?**

This should be the dominant headline.

It should feel confident and human.

Do not use:

-   "Ready to transform your business?"
-   "Take your business to the next level!"
-   "Unlock your digital potential!"
-   "Let's revolutionize your business!"

Avoid generic agency language.

------------------------------------------------------------------------

# SUPPORTING COPY

Use:

> **Tell us what you're trying to solve. We'll help turn it into a
> digital product, business system or experience that works.**

Keep the paragraph around 500--650px maximum width.

Do not create a long contact paragraph.

------------------------------------------------------------------------

# PRIMARY CTA

### Label

`Request a Proposal →`

This should link to:

`/request-a-proposal`

or the final agreed proposal route.

The CTA should be the strongest interactive element in this section.

------------------------------------------------------------------------

# SECONDARY CTA

### Label

`Talk to Us →`

This can link to:

`/contact`

Keep it visually secondary.

Do not add more CTA buttons.

------------------------------------------------------------------------

# OPTIONAL CONTACT DETAIL

A small contact line may appear below the CTAs:

`hello@technomantra.in`

Only display this if it is the verified official contact email.

Do not invent contact details.

------------------------------------------------------------------------

------------------------------------------------------------------------

# VISUAL CONCEPT

The final CTA can subtly reference the site's universe concept without
introducing another large 3D system.

Recommended visual idea:

A very subtle **orbital line / trajectory** behind or around the CTA.

Conceptually:

``` text
                 ·
          ─────────────
       ───              ───
      /    HAVE SOMETHING   \
     |       WORTH BUILDING? |
      \                     /
       ───               ───
          ─────────────
                 ·
```

Keep it extremely subtle.

The purpose is to connect the ending back to the Hero's universe
concept.

Do not add:

-   another planet
-   another full Three.js scene
-   large rotating objects
-   excessive particles
-   neon effects

If an existing lightweight visual element can be reused, prefer reuse
over adding another rendering system.

------------------------------------------------------------------------

# BACKGROUND

Use the existing dark premium visual language.

Possible:

-   deep black / dark navy
-   extremely subtle radial light
-   faint orbital line
-   restrained warm-gold accent

Do not create a completely different background.

The section should feel like the final chapter of the same website.

------------------------------------------------------------------------

# CTA BUTTON DESIGN

## Primary

`Request a Proposal →`

Use the site's established primary CTA treatment.

It should have:

-   clear contrast
-   comfortable padding
-   subtle hover transition
-   visible keyboard focus
-   rounded corners consistent with the existing design system

Hover:

-   subtle brightness change
-   arrow moves slightly
-   no huge scale
-   no glow explosion

------------------------------------------------------------------------

# SECONDARY LINK

`Talk to Us →`

Use a text-link treatment.

Hover:

-   arrow shifts slightly
-   text brightens

No secondary outlined card/button is necessary unless it fits the
established design system.

------------------------------------------------------------------------

# SCROLL EFFECT

Keep this section calmer than the Hero.

When entering the viewport:

1.  Eyebrow appears.
2.  Main heading reveals.
3.  Supporting copy fades in.
4.  Primary CTA appears.
5.  Secondary link follows.
6.  Optional orbital line completes a subtle reveal.

Use a short, controlled stagger.

Do not pin this section.

Do not create a long scroll animation.

Do not create horizontal scrolling.

------------------------------------------------------------------------

# OPTIONAL ORBITAL LINE ANIMATION

If an orbital line is implemented:

On section entry:

-   line draws/reveals subtly
-   opacity increases slightly
-   then settles

The animation should happen once.

Do not continuously rotate the line.

Do not use a heavy shader.

------------------------------------------------------------------------

# MOBILE LAYOUT

The mobile version should remain very clean.

Recommended:

``` text
START SOMETHING

Have something
worth building?

Tell us what you're trying to solve.
We'll help turn it into a digital
product, business system or
experience that works.

[ Request a Proposal → ]

Talk to Us →
```

Use centered alignment unless the existing design system strongly favors
left alignment.

Give the headline enough width to remain visually strong.

Avoid overly large typography that causes awkward wrapping.

------------------------------------------------------------------------

# MOBILE CTA

Primary CTA should be easy to tap.

Use a comfortable touch target.

Secondary link remains below it.

Do not place two tiny buttons side-by-side.

------------------------------------------------------------------------

# RESPONSIVE BEHAVIOR

## Desktop

Large editorial composition with generous whitespace.

## Tablet

Reduce headline size and spacing proportionally.

## Mobile

Single-column layout.

Keep the CTA immediately understandable.

Do not introduce complex interactions.

------------------------------------------------------------------------

# ACCESSIBILITY

Use semantic HTML.

Recommended:

``` html
<section aria-labelledby="contact-heading">
  ...
  <h2 id="contact-heading">Have something worth building?</h2>
  ...
</section>
```

Ensure:

-   CTA is a real link/button
-   keyboard focus is visible
-   sufficient contrast
-   reduced-motion behavior is respected
-   no information depends on animation
-   no interaction requires hover

------------------------------------------------------------------------

# REDUCED MOTION

When:

`prefers-reduced-motion: reduce`

Disable:

-   orbital line animation
-   large entrance movement
-   unnecessary stagger

Keep:

-   content visible
-   CTA usable
-   normal scrolling

Do not hide content because motion is disabled.

-   fake statistics
-   pricing
-   newsletter signup
-   giant contact form
-   multiple forms
-   chat widget
-   social feed
-   giant map

-   unnecessary animations
-   generic marketing slogans

------------------------------------------------------------------------

# TECHNICAL RULES

-   JavaScript / JSX only.
-   No TypeScript.
-   No new packages.
-   Preserve Lenis.
-   Preserve GSAP / ScrollTrigger.
-   Do not modify the completed Hero.
-   Do not modify existing 3D camera behavior.
-   Use semantic HTML.
-   Keep animation lightweight.
-   Avoid React state for animation frames.
-   Respect reduced motion.
-   Reuse existing design tokens.
-   Use verified company/contact information only.
