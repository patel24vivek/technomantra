# TechnoMantra --- Homepage Sections 04 & 05

## Scope

This document defines the next two homepage sections after:

1.  Hero
2.  What We Do
3.  Services

The next sections are:

4.  **Solutions**
5.  **Industries**

The Hero is already complete and must not be modified.

The overall homepage direction remains:

-   Minimal
-   Clean
-   Premium
-   Professional
-   Modern B2B technology company
-   Editorial rather than template-like
-   Strong typography
-   Generous whitespace
-   Restrained use of motion
-   No unnecessary cards
-   No excessive glassmorphism
-   No cyberpunk/gaming styling
-   No visual clutter

The sections should feel like part of one coherent premium website.

------------------------------------------------------------------------

# SECTION 04 --- SOLUTIONS

## Purpose

The Services section answers:

> **What does TechnoMantra provide?**

The Solutions section answers:

> **What business problems can TechnoMantra solve?**

This distinction is important.

Services are capabilities.

Solutions are business outcomes and systems.

The section should communicate that TechnoMantra does not simply sell
development hours. It builds connected digital systems around business
needs.

------------------------------------------------------------------------

# Solutions Content

The official homepage solution categories are:

1.  CRM Solutions
2.  ERP Solutions
3.  Business Automation
4.  Ecommerce Solutions
5.  Marketing Automation

# SOLUTIONS --- CORE CONCEPT

The visual idea should be based on **connection and flow**.

Instead of showing five unrelated cards, visually communicate:

``` text
PEOPLE

PROCESSES
   ↓
DATA
   ↓
SYSTEMS
   ↓
AUTOMATION
   ↓

```

This can be represented using very thin lines, nodes and restrained
motion.

It should feel like a sophisticated system diagram rather than a
dashboard.

# SOLUTIONS --- INTERACTION

This section can use one of the homepage's restrained "cool"
interactions.

## Recommended interaction: Connected System

As the user scrolls:

``` text
CRM
 ↓
ERP
 ↓
AUTOMATION
 ↓
ECOMMERCE
 ↓
MARKETING
```

A subtle line/node system can connect the active solution.

For example:

``` text
                 CRM
                  ●
                 /
                /
        ERP ●──●──● AUTOMATION
              |
              |
          ECOMMERCE
```

The active solution becomes brighter while the others remain subdued.

This should be very subtle.

No neon network effect.

No glowing web of hundreds of lines.

------------------------------------------------------------------------

# SOLUTIONS --- SCROLL EFFECT

Recommended sequence:

### Enter

-   Eyebrow fades upward.
-   Heading reveals.
-   Supporting text appears.

### Solution interaction

As the section scrolls:

1.  CRM becomes active.
2.  Connection line forms.
3.  CRM description appears.
4.  ERP becomes active.
5.  Connection changes.
6.  Business Automation becomes active.
7.  Ecommerce becomes active.
8.  Marketing Automation becomes active.

Use scroll progress rather than independent timers.

The interaction should feel controlled by the user's movement.

# MOTION RULES

For both sections:

Use motion to communicate hierarchy.

Good:

-   Fade
-   Small vertical reveal
-   Line drawing
-   Active-state transition
-   Subtle opacity changes
-   Small position shifts
-   Scroll-synchronized progress

Avoid:

-   Large rotations
-   Constant floating
-   Excessive blur
-   Flashing
-   Large-scale zooms
-   Spinning cards
-   Infinite decorative animations

------------------------------------------------------------------------

# RESPONSIVE RULES

## Desktop

Use richer interaction and optional supporting visual systems.

## Tablet

Reduce complexity and spacing.

## Mobile

Prioritize:

1.  readable content
2.  easy navigation
3.  simple interactions
4.  performance

Do not force desktop interactions onto touch devices.

------------------------------------------------------------------------

# TECHNICAL RULES

When implementing:

-   JavaScript / JSX only.
-   No TypeScript.
-   No new packages unless explicitly approved.
-   Keep solution and industry data separate from presentation
    components.
-   Use semantic HTML.
-   Use existing GSAP and ScrollTrigger.
-   Preserve Lenis integration.
-   Avoid React state every frame.
-   Use refs for continuous animation.
-   Respect reduced motion.
-   Do not modify the completed Hero.
-   Do not modify the existing cinematic camera system.
-   Do not duplicate animation loops.
-   Do not add unnecessary 3D objects.

------------------------------------------------------------------------
